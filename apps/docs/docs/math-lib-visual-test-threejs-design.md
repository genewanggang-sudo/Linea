# Math 库可视化测试方案（Three.js）

## 1. 背景与目标

`@linea/math` 当前主要通过单元测试验证数值正确性。  
为了覆盖“几何形态是否符合预期、交互编辑是否可用、离散结果是否可视化可验”，需要建立一套统一的可视化测试工作台。

本方案目标：

1. 测试范围覆盖 `@linea/math` 可提供的所有功能。
2. 渲染引擎统一使用 Three.js（最新稳定版本）。
3. 为二维几何提供固定视角的交互绘制与验证环境。
4. 建立统一工具面板，支持常用测试操作与状态控制。

---

## 2. 范围定义

### 2.1 In Scope

覆盖 `@linea/math` 的全部能力，包含但不限于：

1. 基础对象：`Vec2`、`Mat3`、`Box2`、`Coord2D`。
2. 曲线对象：`Line2`、`Circle2`、`Arc2`、`Ellipse2`、`EllipseArc2`、`BSpline2`。
3. 曲线通用能力：`pointAt`、`tangentAt`、`derivatives`、`curvatureAt`、`length`、`split`、`trim`、`reverse`、`transform`、`closestPoint`、`boundingBox`。
4. 离散能力：`DiscretizeEngine` + `DiscretizeOptions`。
5. 序列化能力：`dump/load`、`GeomMgr` 注册与反序列化验证。
6. 类型与工具能力：类型谓词、精度阈值、数值工具。

### 2.2 Out of Scope（首版不做）

1. 自动截图回归与像素级比较。
2. CI 自动判定与报告平台。
3. 修改 `@linea/math` 的业务实现逻辑。

---

## 3. 技术选型

### 3.1 渲染引擎

使用 **Three.js 最新稳定版本**，版本策略如下：

1. 依赖声明始终跟随当前稳定主线（非 beta、非 rc）。
2. 升级时先跑本地可视化冒烟，再更新锁文件。
3. 若新版本出现破坏性行为，记录兼容差异并给出回退方案。

### 3.2 职责边界

1. `@linea/math`：只负责计算与几何定义。
2. 可视化应用：负责渲染、交互、状态管理、指标展示。
3. 可视化层不复制数学算法，只消费库接口结果。

---

## 4. 视图与相机规范（二维）

由于当前核心场景是二维线与二维曲线：

1. 所有绘制统一落在 **XOY 平面**（`z = 0`）。
2. 相机固定在 **Z 轴正方向上方** 俯视（朝向原点）。
3. 相机控制仅保留平移和缩放，禁用旋转。
4. 默认显示网格和坐标轴，便于定位与测距。

---

## 5. 交互规范

## 5.1 顶部绘制按钮栏

页面顶部提供一排按钮，作为“绘制模式选择器”。  
建议按钮集（可扩展）：

1. 线段
2. 圆
3. 圆弧
4. 椭圆
5. 椭圆弧
6. B 样条
7. 选择/编辑模式

行为规则：

1. 点击某个按钮后，进入对应绘制模式。
2. 在该模式下可连续绘制同类型对象。
3. **鼠标右键结束当前绘制模式**，回到选择/编辑状态。
4. 再次点击同一按钮可重新进入连续绘制。

## 5.2 连续绘制示例（线段）

1. 点击“线段”按钮后进入线段绘制。
2. 左键两次确定一条线段的起点和终点。
3. 完成后仍停留在线段绘制模式，可继续下一条线段。
4. 右键结束线段绘制模式。

---

## 6. 右侧悬浮工具面板

除顶部按钮栏外，右侧提供浮动工具面板，放常用测试工具。  
最小功能集：

1. 显示/隐藏包围盒。
2. 清空包围盒显示（只清辅助层，不删对象）。
3. 清空场景对象（保留坐标网格与相机）。
4. 显示/隐藏线方向（箭头或方向标记）。
5. 调整离散精度（preset + custom）。
6. 显示当前对象数量、当前模式、选中对象信息。

可自由增强（推荐）：

1. 撤销/重做。
2. 吸附开关（端点吸附、网格吸附）。
3. 批量删除选中对象。
4. 快速开关辅助层（控制点、切线、参数采样点）。

---

## 7. 性能监控小面板（新增）

为便于调参和定位卡顿，页面需增加一个轻量性能面板（默认显示，可折叠）。

建议位置：

1. 桌面端放在画布左下角（不遮挡顶部按钮和右侧工具面板）。
2. 移动端收纳为浮动按钮，点击展开。

最小指标集（实时）：

1. FPS（瞬时 + 1s 平均）。
2. Frame Time（ms/帧）。
3. Scene Object Count（场景对象数）。
4. Draw Calls（每帧调用次数）。
5. Triangles / Lines（渲染负载概览）。
6. Geometry Count / Texture Count（资源计数）。
7. 当前离散分段总量（全部对象折线段总和）。

刷新策略：

1. UI 数值刷新频率 4~10Hz（避免每帧刷新导致额外抖动）。
2. 采样窗口建议 1 秒滑动平均，保留短时峰值。
3. 当 FPS 低于阈值（如 30）时显示黄色告警；低于 20 显示红色告警。

实现建议：

1. 首版可接入 `stats.js`（FPS/帧时基础指标）+ Three `renderer.info`（渲染指标）。
2. 指标面板样式和右侧工具面板统一视觉体系（圆角、半透明、轻阴影）。
3. 提供“重置统计”按钮，方便比较调参前后性能。

---

## 8. 离散参数规范

统一使用 `DiscretizeOptions`，面板提供两类入口：

1. 预设：`coarse` / `medium` / `fine`。
2. 自定义：`chordTol`、`angleTolDeg`、`maxSegments`。

预期行为：

1. 精度越高，分段通常越多。
2. 误差指标应整体下降或保持不增。
3. 任何参数变更需实时重算并刷新渲染与指标。

---

## 9. 测试能力矩阵（全功能覆盖）

按模块给出可视化测试点：

1. 几何构造：参数合法、边界值、退化输入。
2. 曲线求值：点/切线/导数/曲率在关键参数处可视校验。
3. 长度与反参：长度一致性与误差观察。
4. 分割与裁剪：`split/trim` 结果段落与方向正确。
5. 变换能力：平移、旋转、缩放后几何形态正确。
6. 最近点与距离：查询点与投影点可视化验证。
7. 包围盒：`boundingBox` 可视对照对象外接范围。
8. 离散结果：折线逼近、误差变化、分段上限行为。
9. 序列化：`dump/load` 前后形态一致、属性一致。

---

## 10. 页面布局方案（美观与信息层次）

固定布局：

1. 顶部：绘制按钮栏（主工作流入口）。
2. 中央：Three.js 画布（主可视区）。
3. 右侧：悬浮工具面板（辅助控制与指标）。
4. 左下：性能监控小面板（可折叠）。

布局要求：

1. 桌面端优先，移动端可降级为折叠面板。
2. 面板不遮挡主要绘制区域。
3. 所有状态切换有明显视觉反馈。

视觉设计建议（美观大方）：

1. 顶部按钮栏使用分组与图标，主操作按钮高亮，次级操作弱化。
2. 右侧面板采用卡片式分区（绘制、辅助、离散、场景、导入导出）。
3. 颜色语义统一：主色（操作）、成功色（可用）、警告色（性能告警）、危险色（清空/删除）。
4. 使用 8px 间距体系和统一圆角，避免面板杂乱。
5. 字体层级清晰：标题 > 分组标题 > 参数标签 > 数值。
6. 动效轻量：展开/收起、hover、active 反馈，避免花哨动画影响操作。

---

## 11. 性能保护策略（与面板联动）

1. 当 FPS 持续低于阈值时，提示开启“性能模式”。
2. 性能模式下可自动：
   - 降低理论曲线采样密度；
   - 暂停部分辅助层（如切线、方向箭头）实时刷新；
   - 提高参数变更节流时间。
3. 面板中需显示当前是否处于性能模式。
4. 用户可手动强制关闭性能模式，保证调试自由度。

## 12. 验收标准

### 10.1 功能验收

1. 顶部按钮可切换所有绘制模式。
2. 每种曲线支持连续绘制。
3. 右键可结束当前绘制模式。
4. 右侧悬浮面板的核心工具可用。
5. 离散精度调整后，图形和指标实时更新。
6. 方向显示与包围盒显示可独立开关。
7. 场景清空与辅助层清空行为符合定义。

### 10.2 工程验收

```bash
pnpm dev:math-viz
pnpm build:math-viz
pnpm --filter math-visual-test lint
```

## 14. 手工验收 Checklist

1. 相机固定在 Z 轴上方俯视，旋转已禁用。
2. 所有对象绘制于 XOY 平面。
3. 顶部按钮切换曲线绘制模式正常。
4. 线段可连续绘制，右键可结束。
5. 包围盒显示/清空逻辑符合预期。
6. 场景清空后保留基础参考（网格/坐标系）。
7. 方向显示可开关，方向正确。
8. 离散精度调节可见且指标联动。
9. 至少覆盖一组序列化 round-trip 可视验证。
10. 异常输入有提示，不导致页面崩溃。
11. 性能面板可展示 FPS、Draw Calls、对象数等关键指标。
12. 性能告警阈值触发时有明显视觉提示。
